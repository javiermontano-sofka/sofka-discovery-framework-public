Texto corregido:

"Necesito que me ayuden con el tema del banco, ese de la reunión, porque el jefe está presionando y no sé qué hacer con lo del legacy ese que nadie entiende."

Se preserva la estructura informal del usuario. Se mantiene "legacy" como anglicismo técnico aceptado. Se agregaron comas para separar cláusulas y punto final.

2 Cinco Porqués — Causa Raíz

Solicitud superficial: "Necesito ayuda con el tema del banco, el del legacy."

  • ¿Por qué necesita ayuda con el legacy del banco?
    Hay un sistema legado del cliente bancario que genera bloqueo en el equipo o en el discovery.
    Señales: "nadie entiende" — sistema opaco; "ese de la reunión" — discutido previamente sin resolución.
  • ¿Por qué nadie entiende el sistema legacy?
    El sistema carece de documentación, el conocimiento está concentrado en pocas personas, o la tecnología es obsoleta.
    Señal: "legacy ese que nadie entiende" — frustración con opacidad del sistema. [INFERENCIA]
  • ¿Por qué el jefe está presionando?
    Hay un compromiso externo (entregable, reunión, deadline) que depende de avanzar con el análisis del legacy.
    Señales: "el jefe está presionando" — presión de liderazgo; "de la reunión" — presentación próxima.
  • ¿Por qué no sabe qué hacer?
    Le falta una metodología o framework para abordar el análisis de un sistema opaco en contexto de discovery.
    Señal: "no sé qué hacer" — bloqueo de dirección, no de capacidad. [INFERENCIA]

Parada natural en nivel 4. El nivel 5 requeriría contexto organizacional no disponible.

Causa raíz: El usuario necesita una estrategia metodológica para analizar un sistema legacy opaco del cliente bancario, con urgencia por presión de liderazgo y una reunión próxima como deadline implícito.
3 Siete Entonces-Qués — Trazado de Impacto
Nivel Entonces-Qué Tipo de Impacto
1 El equipo tendrá un enfoque claro para abordar el análisis del sistema legacy del banco. Operativo — desbloqueo de equipo
2 El discovery del cliente bancario podrá avanzar con el análisis AS-IS, probablemente bloqueado por la opacidad del legacy. Operativo — progreso de engagement
3 La reunión con el jefe (y posiblemente con el cliente) tendrá contenido sustantivo: hallazgos, riesgos y camino a seguir. Táctico — gestión de stakeholders
4 La presión del jefe se reduce porque hay evidencia de avance y dirección clara. Relacional — dinámica de equipo
5 El engagement con el cliente bancario mantiene credibilidad — Sofka demuestra capacidad de abordar complejidad legacy. Estratégico — relación comercial
6 El análisis del legacy informa el roadmap de modernización, que probablemente es el entregable clave del discovery. Estratégico — valor del engagement

Parada en nivel 6. El nivel 7 sería especulativo sin conocer el contrato y alcance del engagement.

Calibración de profundidad: PREMIUM — la cadena alcanza impacto estratégico (nivel 5-6). La respuesta afecta la credibilidad comercial de Sofka con un cliente bancario.

5 Reformulación
OBJETIVO: Generar una estrategia de análisis AS-IS para un sistema legacy bancario opaco, con enfoque paso a paso que sea ejecutable por el equipo y presentable a liderazgo.

CONTEXTO: Engagement de discovery con cliente del sector bancario. El equipo enfrenta un sistema legacy que carece de documentación adecuada y cuyo funcionamiento interno no está claro ("nadie entiende"). Hay presión de liderazgo con una reunión próxima como deadline implícito. El usuario experimenta bloqueo metodológico, no técnico.

INTENCIÓN: El usuario busca dirección estratégica y metodológica — un framework para abordar la opacidad del legacy — no una solución técnica inmediata. Subtexto emocional: necesita también contención y validación de que el problema es abordable.

RESTRICCIONES:
  - Urgencia temporal: presión de jefe y reunión próxima [EXPLÍCITO]
  - Opacidad del sistema: poca/nula documentación [EXPLÍCITO]
  - Contexto incompleto: tipo de sistema y stack desconocidos [BRECHA]
  - Información de reunión previa no disponible [BRECHA]

OUTPUT ESPERADO: Guía de análisis AS-IS para sistemas legacy opacos con: (1) pasos de exploración sin documentación, (2) técnicas de ingeniería inversa para discovery, (3) template de hallazgos presentable a liderazgo, (4) estimación de esfuerzo.

CALIBRACIÓN: PREMIUM — impacto estratégico en la credibilidad de Sofka con cliente bancario. Cadena de impacto nivel 6.

Preguntas de Clarificación Sugeridas

  • ¿El sistema legacy es un core bancario, sistema auxiliar o integración?
  • ¿Hay acceso al código fuente, bases de datos, o solo a la interfaz?
  • ¿La reunión mencionada es interna (equipo Sofka) o con el cliente?
  • ¿Qué entregable se espera para esa reunión — avance informal o documento formal?
  • ¿Hay personas en el cliente que conozcan el sistema legacy (knowledge holders)?
