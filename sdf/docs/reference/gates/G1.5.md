# Gate G1.5 — Feasibility verdict (7 Sabios Think Tank)

- **When**: After G1 pass, before entering P5 (scenarios).
- **Responsible**: The 7-expert Think Tank (fixed membership):
  1. Research Scientist
  2. Economics Researcher
  3. Systems Theorist
  4. Technology Scout
  5. Integration Researcher
  6. Hardware Systems Engineer
  7. Data Scientist

## Why a separate half-gate

Feasibility is where pre-sales artefacts most often lie — to themselves and to the client. G1.5 exists specifically to stress-test "can this be built?" before any roadmap or cost estimate is drawn.

## Blockers

| # | Condition | Remediation |
|---|-----------|-------------|
| G1.5.1 | Technical feasibility rated <3/5 by any Sabio | Revise scope or technology choice |
| G1.5.2 | Integration risk rated HIGH (>2 unclear protocol boundaries) | Add integration-researcher spike; re-evaluate |
| G1.5.3 | Hardware ceiling exceeded (throughput, latency, storage) | Right-size; add capacity plan |
| G1.5.4 | Economics non-viable (TCO vs realistic market willingness to pay) | Revisit scope; consider phased approach |
| G1.5.5 | State-of-art check negative (literature says "this doesn't work at scale") | Revise approach; escalate to research-scientist |

## Think Tank deliberation format

Each Sabio votes PASS / ADVISORY / BLOCK with a one-paragraph rationale. Unanimous PASS → gate clears. Any BLOCK → gate fails. Mixed → discovery-conductor facilitates reconciliation.

## Pass criteria

- All 7 Sabios at PASS or ADVISORY.
- Blockers resolved or explicitly accepted in risk register.

## Verdict format

```
G1.5 verdict: PASS|FAIL
- Sabios at PASS: N/7
- Blockers: [list]
- Risk register updates: [list]
```
