# Gate G0 — Security + attachment sanity

- **When**: Session start; re-run on every new attachment.
- **Responsible**: risk-controller (lead), attachment-processor (inputs).
- **Mode behaviour**: always strict; `--auto` cannot bypass G0 (security-critical).

## Blockers

| # | Condition | Remediation |
|---|-----------|-------------|
| G0.1 | Secret pattern in priming-rag (AWS keys, tokens, passwords) | Redact; re-run FASE 0 with secret-scrubber |
| G0.2 | Path traversal in locator (`..`, absolute outside repo) | Reject attachment; require clean source |
| G0.3 | Malformed extractor output (crash, empty priming-rag) | Investigate extractor; report bug via antifragile loop |
| G0.4 | Attachment exceeds size ceiling | Chunk or summarize before ingestion |
| G0.5 | MCP server offers privileged tool not declared in `allowed-tools` | Refuse; trust boundary violation |

## Pass criteria

- All attachments ingested without secrets in outputs.
- No path traversal in emitted priming-rag docs.
- MCP server surface matches declared trust boundary.

## Verdict format

```
G0 verdict: PASS|FAIL|ADVISORY
- Attachments scanned: N
- Secrets redacted: M
- Blockers: [list or "none"]
```
