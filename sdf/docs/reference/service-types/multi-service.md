# Multi-Service — Fallback for true multi-workstream engagements

## Scope signal

- Explicit multi-workstream request where no single primary type dominates · "SAS + QA" · "Cloud + Data-AI" combined engagement

## Committee

Permanent triad + transformation-architect (coordinator, lighter than Digital-Transformation) + the sub-committees of each active workstream.

## Pipeline variant

- Runs **N parallel pipelines** (one per workstream) coordinated by a single delivery-manager.
- Shared P0 Plan → divergent P1-P6 → converged P7-P9 (joint roadmap + pitch).
- G1.5 runs once per workstream; G2 is consolidated.

## Typical deliverables beyond P0-P9

- Cross-workstream dependency map.
- Consolidated roadmap with per-workstream tracks.
- Integration blueprint (how the workstreams compose).

## Anti-patterns

- "Digital transformation" with executive sponsor + change imperative → Digital-Transformation, not Multi-Service.
- Two separate small engagements that happen to share a client → route as two separate engagements, not one Multi-Service.

## When in doubt

Digital-Transformation vs Multi-Service: ask "is there a strategic intent driving this, or are these independent needs of the same client?". Strategic intent → Digital-Transformation.
