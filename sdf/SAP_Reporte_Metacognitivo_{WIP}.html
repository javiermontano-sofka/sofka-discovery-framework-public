Bloqueo de Pago para Tarjeta de Credito

DECOMPOSE → SOLVE → VERIFY
"Cual es el mejor procedimiento y tipo de bloqueo para que no se incluyan facturas en la programacion de pago automatica? Ejemplo: compras con Tarjeta credito, que opcion de Bloqueo para pago es recomendable utilizar?"

👁 Entendimiento

Interpreto: Se necesita que facturas especificas (pagadas con tarjeta de credito corporativa) queden excluidas del programa de pago automatico F110, ya que el banco emisor de la TdC ya realizo el pago. HILO

Supongo: El proveedor de la tarjeta (Visa, Mastercard, Amex) esta registrado como vendor en SAP con datos de sociedad. SUPUESTO

Infiero: Se busca una solucion sistematica (no manual caso a caso), idealmente automatizable. INFERENCIA

02

Tolerancias del Control Presupuestal

DECOMPOSE → SOLVE → VERIFY
"Un usuario funcional puede parametrizar los limites de tolerancias de los grupos de cuentas del control presupuestal? o solo los consultores? , Cual es la aplicacion para hacer las respectivas configuraciones?"

👁 Entendimiento

Interpreto: Se pregunta sobre los roles de acceso para configurar tolerancias presupuestales y las transacciones especificas. HILO

Supongo: Se refiere al modulo CO (Budget Availability Control) y/o FM (Funds Management), no a tolerancias de usuario de FI (que es otra cosa). INFERENCIA

Infiero: Hay una necesidad de aclarar responsabilidades entre equipo funcional y equipo de configuracion/consultoria. INFERENCIA

⚙ DECOMPOSE

Sub-problemaDependencia
SP2.1 — Que son las tolerancias y los Account Groups en control presupuestalNinguna
SP2.2 — Que transaccion/ruta se usa para configurarlasSP2.1
SP2.3 — Quien tiene permiso de configurar (funcional vs consultor)SP2.2
SP2.4 — Diferencia entre CO budget control y FM budget controlSP2.1

✅ SOLVE

2.1
Tolerancias: Definen % de uso del presupuesto que disparan advertencia (W) o error (E). Account Groups definen que cuentas de coste/gasto consumen presupuesto. Solo cuentas de P&L, no balance. DOC Confianza: 0.96
2.2
Transaccion: Via SPRO: Controlling > Cost Center Accounting > Budget Management > Maintain Budget Availability Control Profile. No existe un T-code directo comun. DOC Confianza: 0.93
2.3
Permisos: Generalmente solo consultores. Es customizing (SPRO). En S/4HANA Cloud, un key user designado puede verificar settings y crear categorias de planificacion, pero no modificar perfiles de tolerancia. DOC Confianza: 0.90
2.4
CO vs FM: CO controla centros de coste y ordenes con perfiles simples. FM es mas robusto: BCS, multi-nivel, cover eligibility, earmarked funds. FM requiere master data separada (Commitment Items, Funds Centers). DOC Confianza: 0.91

Respuesta: Un usuario funcional estandar NO puede parametrizar tolerancias — es configuracion de customizing (SPRO), requiere perfil de consultor. Un key user designado en S/4HANA Cloud puede verificar settings. La ruta es: SPRO > Controlling > Cost Center Accounting > Budget Management > Maintain Budget Availability Control Profile. El usuario funcional opera dentro de los limites: presupuesta (FMBB), contabiliza, y recibe mensajes de warning/error. Confianza: 0.88

03

Tasas de Cambio: Tipo P vs Tipo M

DECOMPOSE → SOLVE → VERIFY
"Explicacion de las tasas de cambio P y M, cual tasa usa para reconocimiento, costos y gastos reales y que podemos hacer para que sea a tasa promedio del mes el reconocimiento."

👁 Entendimiento

Interpreto: Se necesita (a) explicar la diferencia entre tipo P y M, (b) aclarar cual usa SAP para operaciones reales, y (c) dar opciones para usar tasa promedio mensual. HILO

Supongo: El cliente opera en multi-moneda y ya tiene tipo M configurado en OB08. SUPUESTO

Infiero: Actualmente la tasa se carga diaria o a demanda (tasa spot), y se desea cambiar a promedio mensual para estabilizar el reconocimiento. INFERENCIA

⚙ DECOMPOSE

Sub-problemaDependencia
SP3.1 — Que es tipo M y para que se usaNinguna
SP3.2 — Que es tipo P y para que se usaNinguna
SP3.3 — Cual usa SAP para costos y gastos realesSP3.1, SP3.2
SP3.4 — Como configurar tasa promedio mensualSP3.3

✅ SOLVE

3.1
Tipo M = Standard Translation / Average Rate. Es la tasa por defecto en SAP para posting y clearing. Textual en SAP Help: "the system uses the exchange rate type M (average rate)." DOC Confianza: 0.98
3.2
Tipo P = Convencion comun para planificacion en CO. No es un tipo estandar entregado por SAP — SAP documenta "Planning" como proposito generico, pero "P" como key es creacion del proyecto. Los tipos estandar documentados son: Buying, Selling, Average (M), Historical, Key date. INFERENCIA + WEB Confianza: 0.82
3.3
Para costos y gastos reales: SAP usa tipo M. Configurable por tipo de documento en OBA7. Si no se especifica, M es el default. DOC Confianza: 0.96
3.4
Promedio mensual: 3 opciones: (1) Cargar promedio en tipo M via OB08 cada mes (sencillo, sin customizing). (2) Automatizar con RFTBFF00 o servicio externo. (3) Crear tipo personalizado "PM" en OB07 y asignarlo en OBA7. INFERENCIA + DOC Confianza: 0.90

🔎 VERIFY

VerificacionResultadoNota
Tipo M es average rate por defectoVERDADERO (0.98)SAP Help Portal x2 + Techlorean
Tipo P es key estandar SAPPARCIALEs convencion, no estandar. Verificar en OB07 del sistema.
OBA7 asigna tasa por tipo de documentoVERDADERO (0.95)SAP Community + SAP Note 2959892
OBBS mantiene ratios de traduccionVERDADERO (0.94)Techlorean (tabla TCURF)
💱

Respuesta: Tipo M (average rate) es la tasa que SAP usa por defecto para reconocimiento, costos y gastos reales. Tipo P es una convencion comun para planificacion en CO, pero no es un tipo estandar SAP — verificar en OB07. Para tasa promedio del mes: la opcion mas sencilla es cargar el promedio mensual como tipo M en OB08. Para automatizar: usar programa RFTBFF00. Para separar spot de promedio: crear tipo personalizado en OB07 y asignarlo en OBA7. Confianza: 0.85
