Bloqueo de Pago para Tarjeta de Credito

Excluir facturas de TdC del programa de pago automatico F110
"Cual es el mejor procedimiento y tipo de bloqueo para que no se incluyan facturas en la programacion de pago automatica? Ejemplo: compras con Tarjeta credito, que opcion de Bloqueo para pago es recomendable utilizar?"
Interpreto

Se necesita excluir sistematicamente de F110 las facturas que fueron pagadas con tarjeta de credito corporativa, ya que el banco emisor ya realizo el pago al proveedor. HILO

Supongo

El proveedor de la tarjeta esta registrado como vendor en SAP con datos de sociedad activos. SUPUESTO

Infiero

Se busca una solucion automatizable, no intervenciones manuales caso a caso. INFERENCIA

⚡

Respuesta: Crear clave de bloqueo personalizada (ej: T) en OB27 con parametro "cambio en propuesta permitido" activo. Automatizar asignandola a condiciones de pago especificas para TdC en OBB8. Para proveedores exclusivos de tarjeta, alternativamente bloquear en dato maestro (FK02). F110 excluira esas partidas automaticamente.

Confianza 0.92

Tolerancias del Control Presupuestal

Permisos de configuracion y transacciones aplicables
"Un usuario funcional puede parametrizar los limites de tolerancias de los grupos de cuentas del control presupuestal? o solo los consultores? , Cual es la aplicacion para hacer las respectivas configuraciones?"
Interpreto

Se pregunta sobre roles de acceso para configurar tolerancias y las transacciones especificas. HILO

Infiero

Se refiere a CO (Budget Availability Control) y/o FM (Funds Management), no a tolerancias de usuario de FI. INFERENCIA

Supongo

Hay necesidad de aclarar responsabilidades entre equipo funcional y consultoria. INF

🔒

Respuesta: Un usuario funcional estandar NO puede parametrizar tolerancias — es configuracion de customizing (SPRO), requiere perfil de consultor. Un key user designado en S/4HANA Cloud puede verificar settings. La transaccion es SPRO ruta: Controlling > Cost Center Accounting > Budget Management > Maintain Budget Availability Control Profile. El usuario funcional opera dentro de los limites: presupuesta en FMBB, contabiliza, y recibe mensajes de warning/error.

03

Tasas de Cambio: Tipo P vs Tipo M

Reconocimiento, costos reales, y configuracion de promedio mensual
"Explicacion de las tasas de cambio P y M, cual tasa usa para reconocimiento, costos y gastos reales y que podemos hacer para que sea a tasa promedio del mes el reconocimiento."
Interpreto

Se necesita (a) diferencia P vs M, (b) cual usa SAP para operaciones reales, (c) como configurar promedio mensual. HILO

Supongo

El cliente opera en multi-moneda y tiene tipo M configurado. SUPUESTO

Infiero

Actualmente usan tasa spot diaria y quieren estabilizar con promedio mensual. INF

💱

Respuesta: Tipo M (average rate) es la tasa por defecto para todas las operaciones reales en FI: reconocimiento, costos, gastos. Tipo P es una convencion de implementacion para planificacion en CO — no es key estandar SAP. Para tasa promedio mensual: opcion mas sencilla es cargar el promedio como tipo M en OB08. Para automatizar: RFTBFF00. Para separar spot de promedio: crear tipo personalizado en OB07 y asignar en OBA7.

Confianza 0.85

🔄 Comparativa M vs P

M Standard Translation / Average Rate DOC
  • Tasa por defecto para posting y clearing en FI
  • Facturas, pagos, compensaciones, valoracion FX
  • Si no se configura tipo, SAP usa M automaticamente
  • Tabla TCURR / Transaccion OB08
P Plan Rate (Convencion) INF
  • Usada en CO para planificacion y costeo estandar
  • CK11N, planificacion CeCos, presupuestos
  • Tasa fija para el periodo de planificacion
  • No afecta operaciones reales (FI/MM)
Nota SAP no confirma "P" como key estandar. Es convencion de implementacion. Verificar en OB07.
