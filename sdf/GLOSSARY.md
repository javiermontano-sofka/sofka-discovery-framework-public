# SDF Glossary (plugin-specific)

Monorepo-level glossary: [`../GLOSSARY.md`](../GLOSSARY.md). This file covers **SDF-specific terms** not in the monorepo-level file.

## Pipeline terms

### P0 – P9
Deliverable stages of the SAGE pipeline (separate concept from the ToT meta-phases).

| Stage | Name |
|-------|------|
| P0 | Discovery Plan |
| P1 | Stakeholder Map |
| P2 | Brief Técnico |
| P3 | Análisis AS-IS |
| P4 | Mapeo de Flujos |
| P5 | Escenarios (ToT) |
| P5b | Feasibility Think Tank (7 Sabios) |
| P6 | Solution Roadmap + Cost Estimation |
| P7 | Spec Funcional |
| P8 | Executive Pitch |
| P9 | Handover Operativo |

Full details: `references/ontology/pipeline-orchestration.md`.

### AS-IS
Snapshot of the client's current state. P3 deliverable. Evidence-dense (code refs, config refs, stakeholder quotes). No hypotheses about the future in AS-IS — keep separate from roadmap.

### Ghost menu
Contextual navigation block auto-generated by hooks on every session start. Lives at `.discovery/ghost-menu.md`. Shows current phase, next command, open blockers. Regenerated on every `PostToolUse` hook fire.

### Priming-rag
Markdown document that seeds RAG context. Pattern: `.discovery/priming-rag-{topic}.md`. Auto-generated by FASE 0 attachment ingestion or `/sdf:prime-repo`. Each attachment → one priming-rag doc.

## Operational terms

### Think Tank
7-expert feasibility validation committee active at G1.5. Members: Research Scientist · Economics Researcher · Systems Theorist · Technology Scout · Integration Researcher · Hardware Systems Engineer · Data Scientist. Also called "Los 7 Sabios" in docs.

### Committee
Ad-hoc expert panel drawn from the 49-agent roster for a specific phase. Unlike the Think Tank (fixed membership), the Committee rotates based on `{TIPO_SERVICIO}` and phase needs. `agent-committee.md` defines composition rules.

### Skill vs agent vs command
- **Skill** (`skills/*/SKILL.md`) — auto-activating knowledge unit. Claude selects based on `description` field.
- **Agent** (`agents/*.md`) — invocable subagent. Explicitly delegated to via Task tool.
- **Command** (`commands/*.md`) — user-triggered slash command (`/sdf:*`).

Composition: commands use agents; agents use skills.

## Render + brand terms

### Markdown-Excellence
SAGE's opinionated markdown style. TL;DR at top · dense bullets · Mermaid diagrams inline · ghost menu at bottom. No wall-of-text prose. Rationale: pre-sales readers skim.

### Ghost menu (in deliverable)
A standard trailing section in every deliverable: `## Siguientes pasos` with 3-5 action items + contacts. Distinct from the `ghost-menu.md` runtime artefact above.

## Testing + validation terms

### INSIGNIA (already in monorepo glossary)
See `../GLOSSARY.md#insignia`. SDF-specific clarification: the `heuristic-evals.py` generator produces skill-specific grader assertions from the SKILL.md. Output is flagged `ai-generated` (not `human-reviewed`) until a human signs off.

### Harness
End-to-end skill execution runner. Script: `scripts/ecosystem/run-skill-evals.py`. Reads each skill's `evals/evals.json`, runs prompts via Claude CLI (or mock), scores via `grader.md`, aggregates into benchmark.json compatible with upstream skill-creator's eval-viewer.

## File path conventions

### `.discovery/`
Runtime session artefacts. Gitignored. Contents: `SESSION-README.md`, `SESSION-CLAUDE.md`, `calibration-digest.md`, `ghost-menu.md`, `session-changelog.md`, `session-state.json`, `repo-index.json`, `priming-rag-*.md`, `inbox/`.

### `scripts/ecosystem/logs/`
Batch-script execution logs. Gitignored. Keep historical for debugging multi-plugin operations.

### `evals-workspace/`
End-to-end harness output. Gitignored. Contents per iteration: `eval-{skill}-{case}-{N}/with_skill/{outputs,grading.json,timing.json}` + aggregate `benchmark.{json,md}`.
